Core concept: testing

A test compares observed behavior with an expected result for a chosen input or action.

The game is our worked example of this programming concept.

Begin with this definition. Ask the learner to restate it before tracing the example. Other syntax is review or teacher-supplied support.

Worked example: testing

reports = ['A1 miss', 'B2 hit', 'C3 miss', 'D4 sunk']
expected = ['B2 hit', 'C3 miss', 'D4 sunk']
actual = reports[-3:]
print(actual == expected)  # True

Choose a normal case and an edge case, predict each result, then record actual behavior and decide whether it passes.

Predict first, then run or trace the example. Ask the student to identify the input, operation and result. Use the daily README for the runnable context.

# ['B2 hit', 'C3 miss', 'D4 sunk']
What happens with no reports?

An empty list gives an empty slice. The drawing loop runs zero times.

25–30 minutes: [-3:] means from three items before the end through the end. It also works with one or two items.
